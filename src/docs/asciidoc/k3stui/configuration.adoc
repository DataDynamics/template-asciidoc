[[k3stui-configuration]]
== 설정

[[k3stui-configuration-files]]
=== 설정 파일

바꾸고 싶은 값만 적어도 나머지는 기본값을 씁니다. 파일을 찾는 순서는 <<k3stui-running-config>> 를 참고하십시오.

[cols="1,3", options="header"]
|===
| 파일 | 내용

| `k3stui.yaml` | 클러스터 접속, 노드 경로, 갱신 주기, 시작 화면, 안전 장치, 백업 위치·보관 개수, 외부 도구 경로, 로그 위치
| `keybindings.yaml` | 공통 키와 작업 키 재정의. 작업 ID 는 kbd:[?] 도움말 화면에 표시됩니다
| `theme.yaml` | `dark` / `light` 색상 팔레트
| `views.d/*.yaml` | 리소스별 표시 컬럼 재정의 (<<k3stui-configuration-columns>>)
|===

[[k3stui-configuration-main]]
=== 자주 바꾸는 항목

[source,yaml]
.k3stui.yaml
----
cluster:
  distribution: auto        # <1>
  kubeconfig: ""            # <2>
  context: ""
  host_management: auto     # <3>
ui:
  refresh_interval: 2s      # <4>
  default_view: dashboard
safety:
  read_only: false
  protected_namespaces: [kube-system, kube-public, kube-node-lease]
backup:
  dir: /data2/k3stui-backups
  keep: 7                   # <5>
tools:
  editor: ""                # <6>
----
<1> `auto`, `k3s`, `rke2`, `kubeadm`, `kubernetes` 중 하나입니다.
<2> 비우면 자동으로 찾습니다(<<k3stui-running-kubeconfig>>).
<3> `auto`, `enabled`, `disabled`. `auto` 는 API 서버가 이 호스트에 있을 때만 Host 탭을 켭니다.
<4> 메트릭·호스트 상태의 갱신 주기입니다. 리소스 목록은 watch 로 바로 반영됩니다.
<5> 백업 보관 개수입니다. 넘으면 오래된 것부터 지웁니다.
<6> 비우면 `$EDITOR` → `$VISUAL` → `vi` 순서로 씁니다.

[[k3stui-configuration-columns]]
=== 목록 컬럼 바꾸기 (views.d)

리소스 목록에 어떤 컬럼을 어떤 순서로 보여 줄지 바꿉니다.
내장 컬럼을 빼거나 순서를 바꾸고, 라벨·주석·spec 값 같은 객체 필드를 새 컬럼으로 추가할 수 있습니다.

[source,yaml]
.views.d/pods.yaml
----
columns:              # 적은 컬럼만, 적은 순서대로 표시합니다
  - name: NAME        # 내장 컬럼은 이름만 적습니다
  - name: STATUS
  - name: QOS         # 새 컬럼은 제목과 path 를 적습니다
    path: status.qosClass
    width: 12         # 최대 폭(글자 수)
----

[source,console]
----
$ k3stui --columns pods      # pods 에 쓸 수 있는 내장 컬럼 확인
$ k3stui --check             # 잘못된 값이 있으면 [WARN] 으로 알려 줍니다
----

NOTE: 설정은 시작할 때 한 번 읽습니다. 파일을 고친 뒤에는 {tool} 을(를) 다시 실행하십시오.
