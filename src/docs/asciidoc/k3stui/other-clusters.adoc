[[k3stui-other-clusters]]
== 다른 Kubernetes 클러스터에서 사용

{tool} 은(는) 시작할 때 배포판과 API 서버 위치를 판별해 동작 모드를 정합니다.

[cols="2,3", options="header"]
|===
| 상황 | 동작

| K3s·RKE2·kubeadm 서버 노드에서 실행 (API 서버가 이 호스트) | 모든 기능을 씁니다. 탭은 Host 를 포함해 7개입니다
| 원격 K3s·RKE2·kubeadm, 관리형 클러스터(EKS, GKE, AKS 등) | Host 탭과 대시보드 호스트 패널을 숨기고 연결 정보를 보여 줍니다. 탭은 6개입니다
|===

배포판 판별:: API 서버 버전(`+k3s`, `+rke2`)을 보고, 알 수 없으면 `kube-system/kubeadm-config` ConfigMap 으로 kubeadm 을 확인합니다.
그래도 모르면 일반 Kubernetes(`kubernetes`)로 봅니다.
로컬 판별:: API 서버 주소가 루프백이거나 이 호스트의 네트워크 인터페이스 IP 이면 로컬로 봅니다.
kubectl:: 로컬 K3s 면 `k3s kubectl`, 로컬 RKE2 면 `<data-dir>/bin/kubectl`, 그 밖에는 PATH 의 `kubectl` 을 씁니다.

[[k3stui-other-clusters-examples]]
=== 사용 예

[source,console]
----
$ k3stui --kubeconfig ~/.kube/config --context prod-cluster    # 원격 클러스터
$ k3stui --context kind-dev                                     # $KUBECONFIG 또는 ~/.kube/config 의 context
$ sudo k3stui --distribution kubernetes                         # K3s 노드지만 리소스 관리만 쓰기
----

자주 붙는 클러스터는 사용자 설정 파일을 만들어 두면 옵션 없이 실행할 수 있습니다.

[source,console]
----
$ mkdir -p ~/.config/k3stui
$ cp conf/examples/k3stui-k8s.yaml ~/.config/k3stui/k3stui.yaml
$ k3stui --context prod-cluster
----
